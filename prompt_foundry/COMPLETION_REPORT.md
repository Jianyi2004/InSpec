## 🎯 需求实现详情

### 1. 版本管理 ✅

**需求**：对 Prompt 进行版本管理，同一个版本的所有文字 prompt、ICL 图片等放到一个规范命名的文件夹中

**实现**：
- ✅ 版本文件夹格式：`v{major}.{minor}_{tag}_{timestamp}`
- ✅ 示例：`v1.0_initial_20260129_102530`
- ✅ 每个版本包含：
  - `prompt.txt` - 完整 prompt
  - `icl/` - 示例图片目录
  - `examples_metadata.json` - 示例元数据
  - `version_info.json` - 版本信息

**文件结构**：
```
prompts/DCDU安装/
├── prompt.txt                    # 当前工作版本
├── icl/                          # 当前示例图片
└── versions/                     # 版本历史
    ├── v1.0_initial_20260129_102530/
    ├── v1.1_bugfix_20260129_143022/
    └── v2.0_major_update_20260130_091500/
```

### 2. 差异对比 ✅

**需求**：用户点击修改 Prompt 时，显示现在的 Prompt 内容，修改后显示修改的地方（类似 git diff）

**实现**：
- ✅ 加载当前版本按钮 - 显示原始内容
- ✅ 实时差异对比 - 修改后自动显示差异
- ✅ 统计信息 - 新增/删除/修改行数
- ✅ ICL 图片变化 - 检测图片的增删

**差异显示格式**：
```diff
📊 差异统计
- ➕ 新增行数: 5
- ➖ 删除行数: 2
- 🔄 修改行数: 3
- 📝 总变更: 10

🖼️ ICL 图片变化
- ➕ 新增: icl/example_3.png

--- 原版本
+++ 修改后
@@ -15,7 +15,7 @@
-若图片中只有一个DCDU面板，直接进入下一步
+若图片中有1-2个DCDU面板，可以进入下一步
```

### 3. 保存功能 ✅

**需求**：修改后的 prompt 可以保存回 prompts 中的对应文件夹，按照版本号命名，用户可以写简单的 tag 放在文件名中

**实现**：
- ✅ 版本号自动递增（minor: v1.0→v1.1, major: v1.9→v2.0）
- ✅ 自定义标签输入框
- ✅ 版本类型选择（minor/major）
- ✅ 一键保存到版本文件夹
- ✅ 自动复制 ICL 图片和元数据

**保存界面**：
```
┌─────────────────────────────────┐

## 📖 使用流程示例

### 场景 1: 修改现有 Prompt

```
1. 进入「✏️ 修改 Prompt」标签页
2. 选择 Prompt: DCDU安装
3. 点击「📂 加载当前版本」→ 查看原始内容
4. 修改类型: 规则放宽
5. 修改需求: 允许最多1个浮动螺丝缺失仍判PASS
6. 点击「🔧 修改 Prompt」
7. 查看差异对比 → 确认修改正确
8. 查看图片检查 → 确认无缺失图片
9. 填写标签: relax_screw_rule
10. 选择类型: minor
11. 点击「💾 保存版本」
12. 结果: v1.1_relax_screw_rule_20260129_143022
```

### 场景 2: 查看版本历史

```
1. 进入「📚 版本管理」标签页
2. 选择任务: DCDU安装
3. 点击「📋 查看版本历史」
4. 查看所有历史版本的详细信息
