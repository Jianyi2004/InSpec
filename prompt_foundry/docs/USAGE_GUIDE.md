# Prompt Foundry 使用指南

## 🎯 新功能概览

### ✅ 已实现的增强功能

1. **版本管理系统** - 自动管理 Prompt 版本历史
2. **差异对比功能** - 类似 git diff 的可视化对比
3. **保存功能** - 支持版本号和自定义标签
4. **示例图片检测** - 自动检测并提示缺失的图片

## 📁 版本管理系统

### 版本文件夹结构

```
prompts/
└── DCDU安装/
    ├── prompt.txt                    # 当前版本（工作区）
    ├── icl/                          # 当前示例图片
    ├── examples_metadata.json        # 示例元数据
    └── versions/                     # 版本历史
        ├── v1.0_initial_20260129_102530/
        │   ├── prompt.txt
        │   ├── icl/
        │   ├── examples_metadata.json
        │   └── version_info.json
        ├── v1.1_bugfix_20260129_143022/
        │   ├── prompt.txt
        │   ├── icl/
        │   └── version_info.json
        └── v2.0_major_update_20260130_091500/
            ├── prompt.txt
            ├── icl/
            └── version_info.json
```

### 版本命名规范

**格式**: `v{major}.{minor}_{tag}_{timestamp}`

**示例**:
- `v1.0_initial_20260129_102530` - 初始版本
- `v1.1_bugfix_20260129_143022` - Bug 修复
- `v1.2_optimize_20260129_150000` - 优化改进
- `v2.0_major_update_20260130_091500` - 大版本更新

**版本类型**:
- **minor**: 小版本更新（v1.0 → v1.1 → v1.2）
  - 适用于：小幅修改、Bug 修复、规则微调
- **major**: 大版本更新（v1.9 → v2.0）
  - 适用于：重大重构、架构调整、大量规则变更

**常用标签**:
- `initial` - 初始版本
- `bugfix` - 修复问题
- `feature` - 新增功能
- `update` - 常规更新
- `optimize` - 优化改进
- `refactor` - 重构
- `rule_relax` - 规则放宽
- `rule_strict` - 规则收紧

## 🚀 使用流程

### 1. 生成新 Prompt

**步骤**:

1. 进入「📝 生成 Prompt」标签页
2. 填写任务名称（例如：RRU天线接地检查）
3. 填写需求描述（简单描述检查内容和判断标准）
4. （可选）选择参考 Prompt
5. （可选）填写关键概念和检查点
6. 点击「🚀 生成 Prompt」
7. 等待生成完成，查看结果
8. **查看图片检查提示** - 系统会自动检测缺失的示例图片
9. 填写版本标签（例如：initial）
10. 选择版本类型（minor/major）
11. 点击「💾 保存版本」

**示例图片提示**:

如果生成的 Prompt 中引用了示例图片，系统会显示：

```
⚠️ 需要上传的示例图片

以下图片在 prompt 中被引用，但可能尚未上传：

- icl/example_1.png
- icl/example_2.png

💡 操作建议：
1. 前往「示例管理」标签页上传这些图片
2. 或者在保存 prompt 后，将图片放到对应的 icl/ 目录下
```

---

### 2. 修改现有 Prompt

**步骤**:

1. 进入「✏️ 修改 Prompt」标签页
2. 选择要修改的 Prompt
3. 点击「📂 加载当前版本」- **查看原始内容**
4. 选择修改类型（规则放宽/规则收紧/概念补充/流程调整）
5. 填写修改需求（例如：允许最多1个浮动螺丝缺失仍判PASS）
6. 点击「🔧 修改 Prompt」
7. 等待修改完成
8. **查看差异对比** - 系统自动显示修改的地方
9. **查看图片检查提示** - 检查是否有新的图片需求
10. 确认无误后，填写版本标签
11. 选择版本类型
12. 点击「💾 保存版本」

**差异对比示例**:

```diff
📊 差异统计
- ➕ 新增行数: 5
- ➖ 删除行数: 2
- 🔄 修改行数: 3
- 📝 总变更: 10

🖼️ ICL 图片变化
- ➕ 新增: icl/example_3.png
- ➖ 删除: icl/old_example.png

--- 原版本
+++ 修改后
@@ -15,7 +15,7 @@
 ## 判断流程
 
 ### 第一步：识别目标设备
-- 若图片中只有一个DCDU面板，直接进入下一步
+- 若图片中有1-2个DCDU面板，可以进入下一步
+- 若图片中有3个或以上DCDU面板，需要用户明确标注
```

**重大更新**:
- `v2.0_major_refactor` - 大版本重构
- `v2.1_new_workflow` - 新的判断流程

### 2. 修改 Prompt 的工作流

```
1. 加载当前版本 → 查看原始内容
2. 描述修改需求 → 让 AI 理解意图
3. 生成修改结果 → AI 自动修改
4. 查看差异对比 → 确认修改正确
5. 检查图片需求 → 确保示例完整
6. 保存新版本 → 记录变更历史
```

### 3. 示例图片管理

**命名规范**:
- `example_1.png`, `example_2.png` - 按顺序编号
- `positive_example_1.png` - 正例
- `negative_example_1.png` - 反例
- `edge_case_1.png` - 边界情况

**说明要求**:
- 详细描述图片展示的内容
- 说明这是正例还是反例
- 指出关键判断点
- 解释为什么这样判断

## 🔧 技术细节

### 版本信息文件

每个版本文件夹中的 `version_info.json`:

```json
{
  "version": "v1.1",
  "major": 1,
  "minor": 1,
  "tag": "bugfix",
  "timestamp": "20260129_143022",
  "folder_name": "v1.1_bugfix_20260129_143022",
  "created_at": "2026-01-29T14:30:22.123456",
  "prompt_length": 7850
}
```

### 差异对比格式

使用标准的 unified diff 格式：
- `---` 和 `+++` 表示文件头
- `@@` 表示差异块的位置
- `-` 开头的行表示删除
- `+` 开头的行表示添加
- 空格开头的行表示上下文

## 🐛 常见问题

### Q1: 修改后的 Prompt 没有显示差异？

**A**: 确保先点击「📂 加载当前版本」，让系统知道原始内容。

### Q2: 保存版本时提示缺少图片？

**A**: 前往「🖼️ 示例管理」标签页上传缺失的图片，或者先保存版本，稍后手动添加图片到 `icl/` 目录。

### Q3: 如何回滚到历史版本？

**A**: 
1. 进入「📚 版本管理」查看历史版本
2. 找到对应的版本文件夹路径
3. 手动复制 `prompt.txt` 到任务根目录
4. 或者在下次修改时，可以基于历史版本进行修改

### Q4: 版本号如何选择？

**A**: 
- 小改动用 minor（v1.0 → v1.1）
- 大改动用 major（v1.9 → v2.0）
- 不确定时默认用 minor
