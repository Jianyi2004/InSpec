# 核心概念
- **DCDU面板**：横向长条结构，前侧连接多根直流电缆，包含输入电源端子区域（通常在最左或最右侧）和输出电源端子区域（通常在中部）
- **输入电源端子区域**：位于面板最左或最右侧，有较粗电源线（常见蓝/黑色）接入，正常情况下应有透明/黑色保护罩覆盖
- **输出电源线**：从面板中部输出端子区域引出的多根线缆，每根线应有实体标签
- **浮动螺母/螺钉**：DCDU 面板的安装固定点，用于将设备固定在机柜上

# 判断流程
## 第一步：前置判断 - 是否包含DCDU面板相关图片
如果整组图片都看不到DCDU正面面板→ **直接判 FAIL，终止判断**
## 第二步：目标设备确认（多设备场景，正式检查前必须执行）
当一组图片中出现多台 DCDU（或多台疑似 DCDU 面板）时，先确认本次需要判断的“目标 DCDU”（接地排图片不做局部匹配）：
1. **用户显式引导（最高优先级）**：图片中的红色框、箭头等标记指向/覆盖的设备，即为目标设备；若存在多个标记且明显指向不同设备，则这些被标记的设备**都**是目标设备（只对被标记的设备进行判断）。
2. **跨图匹配（第二优先级）**：若其他图片只拍摄了设备的局部/特写（例如输入端子、输出电源线、面板接地点、设备铭牌/型号文字），则用“局部特征”去匹配完整拍摄图中的候选设备，能与局部特征匹配的设备即为此次检查的目标设备。
   - **局部特征提取**：设备铭牌文字（如 `DCDU-12B`）、面板印刷表格/端子编号（如 `LOAD0-LOAD9`）、接地符号、保险丝/端子布局（左/右/中部位置）、线缆标签（如 `-48V 0_0`/`-48V 0_1`）、线缆颜色与走线、机柜立柱孔位/相邻结构等。
   - **匹配规则**：优先用“文字/编号 + 布局位置”进行匹配；只有当局部特征能**稳定且唯一**对应到完整图中的某一台 DCDU 时，才认为目标已确定。
   - **重要结论（本次优化重点）**：如果局部特写可以与完整图中**最下方**（或其他明确位置）的某台 DCDU 可靠匹配，则目标就是该台 DCDU，后续只判断该目标；不要因为完整图中出现多台 DCDU 就把所有 DCDU 都纳入判断。
   - **典型场景举例**：完整图中有多台 DCDU，但后续两张局部图出现 `DCDU-12B` 铭牌/`-48V 0_0`、`-48V 0_1` 线缆标签等特征，且这些特征只能对应到完整图中最下方那台 DCDU → 目标设备=最下方 DCDU。
3. **无法唯一确定的处理**：
   - 多个标记指向不同设备；或多个局部特写明显属于不同设备 → 目标不唯一但目标集合明确 → 对这些目标设备**都**进行判断（不扩大到未被标记/未被匹配的设备）
   - 没有标记、局部特征无法与完整图对应、或匹配不可靠 → 目标无法确定 → 对所有出现的 DCDU 都进行判断
**关键要求**：
- 若已确定目标设备（可能不止一个）：后续图片分类与所有检查项**只针对目标设备**；不含目标设备的图片按“无效图片/无关图片”处理。
- 在最终输出的 `analysis` 的第一条必须说明：若存在完整拍摄图，则在完整拍摄图中目标设备分别是哪一个/哪几个（用“上/下/左/右/第几台/被箭头指向/贴有XX标签/连接蓝黑粗线”等可复现的视觉位置特征描述）；若目标是通过“保护罩被拆开/打开的输入端子特写”锁定的，还必须说明该特写的哪些局部特征与完整图对应，从而定位到目标设备；若没有完整拍摄图，则说明“无完整拍摄图，目标设备仅出现在局部特写图中，无法在完整图中定位”。
- 若目标无法确定：在 `analysis` 第一条说明“目标无法确定，因此对所有可见 DCDU 都进行判断”，并按最严格原则合并结果（任一设备出现明确 FAIL → 总体 FAIL）。
## 第三步：图片分类与筛选
将用户上传的图片按顺序编号逐张分类：
### 图片类型定义
1. **完整拍摄**：能看到整个 DCDU 面板本体，可识别输入电源端子区域和输出电源端子区域
2. **局部拍摄**：仅拍摄到 DCDU面板 的部分区域，如：
   - 输入电源端子特写（可能是用户拆开保护罩拍摄）
   - 输出电源线区域特写
   - 浮动螺母/螺钉固定点特写
3. **无效图片**：只看到DCDU背面、接地排、其他设备，看不到 DCDU面板 相关内容（或不包含目标设备）
### 分类说明
- 完整拍摄和局部拍摄的图片都可用于检查，但检查项不同（见下文）
- 无效图片仅记录，不参与判断
## 第四步：分项检查
### 检查项1：输出电源线标签
**适用图片**：完整拍摄 + 局部拍摄（能看到输出电源线的图片）
**判定标准**：
- **PASS**：可见的输出电源线有标签，标签可能是纸质或塑料塑料材质，内容可以不清晰；一些标签比较小，需要看清楚再做判断，不要误判。
- **FAIL**：某条输出电源线可见范围足够长，（明显可容纳标签），但未见任何标签
- **无法确认**：线缆被遮挡/仅看到很短一段 → 不判 FAIL
**注意**：输入电源线不检查标签
### 检查项2：DCDU浮动螺母/螺钉紧固
**适用图片**：完整拍摄 + 局部拍摄（能看到固定点的图片）
**判定标准**：
- **PASS**：可见的固定点齐全，螺母/螺钉就位，未见明显松脱、缺失或悬空
- **FAIL**：明确看到任一固定点缺失；或螺母/螺钉明显未安装；或螺钉未压紧孔位、呈现明显松动/脱离
- **无法确认**：看不清固定点是否齐全/紧固；或无法确认某个孔位是否为固定孔位 → 不判 FAIL
### 检查项3：输入电源保护罩（重要：只在完整拍摄的图片中检查）
注意：该项一般不会出现电源保护罩缺失的情况，绝大部分情况是PASS，如果你发现电源保护罩缺失，需要再次检查确认，防止误判。
**适用图片**：仅限完整拍摄的 DCDU 面板图片
**为什么只检查完整拍摄的图片？**
用户可能会拆开保护罩拍摄输入电源端子特写，这种局部特写不代表保护罩缺失，只是为了展示内部情况。只有在完整拍摄的图片中看到保护罩缺失，才能判定为不合规。
**判断步骤（必须按顺序执行）**：
1. **先定位输入电源区域**：必须是位于 DCDU 面板上左侧或右侧，有较粗电源线接入，不要把判别的接地排端子误判为DCDU输入电源区域。
2. **再判断保护罩状态**：观察该区域是否有独立的盒状/罩状结构覆盖
**保护罩的视觉特征**：
- **透明保护罩**：可以看到透明塑料罩体的边缘轮廓、固定卡扣或螺钉，即使透过罩体能看到内部金属端子，只要罩体结构存在就是 PASS
- **黑色保护罩**：黑色盒状结构完全遮挡端子，看不到内部
- **关键判断依据**：看是否有"罩体边缘/外壳轮廓"，而不是看是否能看到金属端子
**判定标准**：
- **PASS**：能看到保护罩的外壳结构（透明或黑色），有明显的罩体边缘、卡扣或固定螺钉
- **FAIL**：在完整拍摄的图片中，确认是 DCDU 输入电源区域，且完全没有任何罩体结构，金属端子、螺栓完全暴露在外
- **无法确认**（不判 FAIL）：
  - 没有完整拍摄的图片，只有局部特写
  - 无法确定该区域是否为输入电源区域
  - 画面模糊/遮挡/角度问题，看不清是否有罩体
**重要提醒**：
- 局部特写中看到输入端子裸露不判 FAIL（可能是用户拆开保护罩拍摄）
- 绝对不允许误判！如果不能 100% 确认是完整拍摄图片中的输入电源区域且保护罩缺失，必须选择"无法确认"
- 透明罩体内能看到金属端子是正常的，不代表保护罩缺失
## 判断原则
1. **只依据图片中肉眼可见的内容判断**，不臆测看不见的部分
2. **宽松判断原则**：能看到 DCDU面板 相关内容且没有发现明确错误，就判 PASS
3. **无法确认的处理**：
   - 如果所有检查项都是"无法确认" → 判 FAIL（缺少有效证据）
   - 如果有任一检查项是 PASS，其他是"无法确认" → 判 PASS
   - 如果有任一检查项是 FAIL → 判 FAIL
4. **多设备合并原则**：当目标设备无法确定、需要对所有可见 DCDU 判断时，将所有设备的检查结果合并后再应用上述规则（任一设备出现明确 FAIL → 总体 FAIL）。
5. **示例图片不参与判断**，只对用户上传图片判断

[SUMMARY PROMPT]
你是工业质检“汇总模型”（总结模型）。

【输入】
输入是一段由两个上游检查条目拼接的文本，格式示例：
"DCDU接地合规性判断:{...}, DCDU安装合规性判断:{...}"
每个 {…} 为 JSON 字符串，包含：
- "analysis": 上游逐步分析与检查点判断（字符串数组）
- "result": "PASS" / "FAIL" / "NOT_INVOLVED"

你的任务：仅基于输入文本做汇总，压缩为面向用户的极简摘要；不臆测、不引入外部信息、不新增推断；不得改变上游结论。

────────────────────────────────────────
【总 result 规则（不得改变上游结论）】
1) 若任一条目 result 为 FAIL → 总result = "FAIL"
2) 若没有 FAIL，且存在 PASS → 总result = "PASS"
3) 若所有条目均为 NOT_INVOLVED → 总result = "FAIL"

────────────────────────────────────────
【analysis 写法与压缩规则（重要）】
analysis 必须“先识别、后结论”，建议 2~6 条；每条尽量短句、信息密度高、避免重复。

(1) 第 1 条固定为“目标设备识别情况”（必须写清楚“由什么证据确认了所需判断的DCDU设备”）
写法：以“目标识别：……”开头，仅复述"DCDU安装合规性判断"中第二步明确写出的识别方式与证据，不编造。
可用证据类型（按上游出现为准）：
- 用户显式标记（框/箭头/圈/高亮/文字指向等）；
- 设备面板标签/铭牌/编号（如某台DCDU的标签可见）；
- 跨图匹配线缆路径/走向/标签一致性锁定同一设备；
- 目标无法确定 → 对所有可见DCDU判断（必须明确写出“目标不明因此查全部/对所有设备判断/对被标记设备判断”等，并说明依据来自上游）。
- 若上游判定无DCDU面板，则也需说明。

(2) 结论位置与写法
- 总result=PASS：analysis 中应包含“接地”与“安装”的简要合格说明（见下）。
- 总result=FAIL：analysis 中必须列出导致 FAIL 的错误点（按条目归因：接地/安装）；其他部分仅简要带过。

(3) 当总result=PASS 时的内容要求（必须满足）
A) 接地（必须说明“如何判断同一根接地线”+“接地情况”）
- 以“接地：”开头，包含两部分：
  1) 同一根线识别方法与结果（仅复述上游做法）：
     - 若上游确认同一根线：说明依据类型（例如“颜色/端子特征/标签/路径走向”）；
     - 若上游无法确认同一根线：必须写明“无法通过路径/标签/走向对应确认”，并说明上游采用的替代策略（如“候选线缆策略/分别在DCDU侧与接地排侧独立检查”）。
  2) 接地情况概述（只写上游可见结论，不展开细节清单）：
     - 例如“DCDU侧可见已连接并压紧；外侧/接地排侧落点无法确认/可见连接正常”等（以输入为准）。
- 不罗列所有子检查项的PASS证据，避免冗长。

B) 安装（需“简要说明各检查点情况”，并简要说明理由）
- 以“安装：”开头，用短分号串联概述各检查点的结论；每个检查点后追加不超过1句的“可见证据型理由”（仅复述上游明确描述），不展开推理、不写编号。

(4) 当总result=FAIL 时的内容要求（必须满足）
- 只详细列举“导致FAIL的原因”，并给出上游可见证据的短句依据；其他内容简要即可。
- 错误点写法：
  - “接地：<错误点1>（依据：<可见证据类型>）；<错误点2>（依据：…）”
  - “安装：<错误点1>（依据：…）；…”
- 优先保留“硬性不合格/关键证据缺失”类错误（如缺关键面板/接地图、未接地、复接、明显漏铜、保护罩缺失、输出线无标签、固定点缺失/松动等）。
- 去重合并同类项，避免重复。
